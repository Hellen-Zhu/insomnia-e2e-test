# E2E Test Framework — Working Rules

Playwright + TypeScript + playwright-bdd, Page Object Model. Gherkin scenarios
compile to Playwright specs via `bddgen` at build time (`.features-gen/`, git-ignored).

## Commands

```bash
npm test                              # bddgen && playwright test (chromium project)
npx bddgen export                     # list all registered steps (the vocabulary menu)
npx bddgen && npx tsc --noEmit && npx eslint . && npx playwright test --list   # verification chain
```

Run the full verification chain after every change. `playwright test --list` does NOT
execute lazy-loaded code (YAML data index, fixtures) — path/data bugs need a real run.

## Directory = boundary

| Directory | Role | Hard rule |
|---|---|---|
| `test/features/` | Gherkin scenarios (business language) | no selectors, URLs, or technical detail |
| `test/steps/` | one Gherkin line ↔ one call (thin glue) | calls flows/pages only; no logic, no locators |
| `fixtures/` | dependency injection: base → tradePortal → {trade, product} | steps of one scenario must come from one test instance or its ancestors |
| `pages/` | **the only place Locators may exist**; one page = one folder | pages never call other pages, never see Gherkin |
| `pages/components/` | design-system component objects (host → internals) | zero business words |
| `flows/` | cross-page orchestration + arrival assertions | zero locators |
| `api/` | data-seeding clients (never API functional tests) | no page awareness |
| `data/` | typed loader/index for test-data (code) | — |
| `test-data/` | YAML cases/presets + .dat assets | read-only at runtime; deep-copied on read |
| `config/` | env + credentials (`users.ts` role map) | secrets never hardcoded beyond test creds |

`test/` is the entire playwright-bdd coupling surface (see `docs/playwright-bdd-exit.md`).

## Locator rules (pages/ only)

1. Fixed elements → `readonly` class-head fields; **never construct locators in method bodies**.
2. Genuinely runtime-parameterized (`row(id)`, `input(field)`) → named private factory methods.
3. Factory + literal callers (`btn('save')`) → promote each literal to a field.
4. A component with ≥3 parameterized testid rules → class-head `TID` template table
   (example: `pages/components/dynamic-action-modal.ts`).
5. ⚠️ ES2022: field initializers run BEFORE the constructor body — locators depending on
   same-class constructor params must be assigned in the constructor.

## Gherkin vocabulary

Rules live in `docs/gherkin-style.md` (six rules). Essentials: third-person named roles
(the maker / the checker); Then statements without "should"; business states are closed
phrases, not parameters; mechanism qualifiers are a closed set (`via api`, `from the case
data`, `from the blotter`, `from the trade details page`). Reuse existing steps first —
`npx bddgen export` is the menu; an unregistered phrase fails bddgen (this is a feature).

## Test data

- caseId lives in the scenario title (`TRADE-001 - description`); steps read the same
  case via `getCase<T>(caseId)` / `getPreset<T>(namespace, alias)` from the global index.
- YAML top-level keys are namespaces: `cases` (globally unique caseIds, `<MODULE>-<seq>`)
  and `<kind>_preset`. Same file holds presets and cases — do not split.
- Preconditions seed via API (`Given ... via api`); UI is for the behavior under test.

## Iron rules

- **Never edit `.features-gen/`** — generated by bddgen, overwritten on every run.
- **Login is UI-only** — no session injection, no cookie caching (app does not support it).
  Role switch mid-scenario = clear cookies + `loginFlow.loginAs(role)`.
- Tests never write to `test-data/` at runtime (editing YAML as source in git is fine).
- **Language: English only** for all new code, comments, docs, and commit messages.
  When editing a file that still contains Chinese, translate what you touch.
- Commit/push only when the user explicitly says "push".
- `feature/plain-playwright` is a mirror branch, synced only on explicit request.

## AI agents

**Story TDD lifecycle** (features are written before the app feature is built):

```
/story-design  (pre-dev)   AC table → uncompiled drafts in specs/<STORY-ID>/
                           (feature draft + data skeleton + story-extracted notes;
                           business language only — no UI speculation of any kind)
      ↓  frontend/backend development — the draft is the acceptance contract
/story-implement (post-dev) promote into test/features/ → bddgen worklist →
                           ALL UI judgment happens here (journeys, layers, testid
                           audit) → implement deltas → whole-module regression
```

`specs/` is deliberately outside the bddgen globs — design drafts never compile.
The compile gate starts at promotion into `test/features/`.

Agents (`.claude/agents/`): `bdd-designer` (design-phase drafting, text-only, no
browser); `playwright-test-planner` (brownfield exploration of an implemented app);
`playwright-test-generator` (implement one scenario against the live app);
`playwright-test-healer` (fix failures at the right source layer — never
`.features-gen/`). Seed specs for agent page setup live in `test/seed/`
(agent-only `seed` project in playwright.config.ts).

Skills (`.claude/skills/`): `/story-design`, `/story-implement` (the lifecycle
above), `/new-module` (greenfield scaffold; story skills hand off to it when a
story opens a brand-new module, at implement time only).
